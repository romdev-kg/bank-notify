## Остаточные ограничения

- POCO F6 Pro / HyperOS и API 37 не проверены на устройстве. На телефоне пользователя помогла
  повторная выдача доступа; точная системная причина не установлена, обход через PackageManager не добавлен.
- Android может задерживать задания из-за сети, батареи, force-stop; 5 минут — планируемый обычный интервал.
  Если недоступны одновременно база и планировщик, остаётся аварийный WorkManager retry.
- Доставка остаётся at-least-once: если Telegram принял сообщение, а процесс умер до записи подтверждения,
  возможен дубль. Отправленные ключи не удаляются, агрессивное объединение одинаковых платежей не применяется.
- Парсер — эвристика. Новые форматы дат, телефонов и масок карт нужно подтверждать обезличенными реальными
  примерами; неподтверждённые расширения, способные превратить номер в сумму, не добавлялись.
- Журнал best-effort: последние ещё не записанные события могут потеряться при внезапном завершении/сбое диска.
- Пока защищённые настройки недоступны, новые уведомления могут не приниматься; сохранённая очередь не удаляется.
- Прямой Test — явная диагностическая отправка пользователя; автоматические повторы оплат сохраняют retry_after.
- Очистка отправленных строк/ключей, более тонкие R8-правила, pin GitHub fallback actions по SHA и сокращение
  дисковых записей журнала остаются отдельными оптимизациями, не подтверждённой потерей оплат.
