# BankNotify

Android-приложение для перехвата push-уведомлений из банковских приложений (Сбербанк, Россельхозбанк) и отправки данных платежей в Telegram-группу.

## Функциональность

- Перехват push-уведомлений из Сбербанка и Россельхозбанка
- Автоматический парсинг суммы, типа операции, номера счёта
- Отправка в Telegram Bot API
- Постоянная очередь доставки в Room Database
- Журнал событий и счётчики пропусков
- Защита токена Telegram (EncryptedSharedPreferences)
- Запуск при перезагрузке устройства

## Требования

- Android 8.0+ (API 26+)
- Android SDK 37.2, Build Tools 36.0.0
- JDK 25 LTS для сборки (байткод JVM 17), Gradle 9.7.0 через wrapper

## Настройка

### 1. Включить разрешение "Слушатель уведомлений"

На телефоне:
```
Параметры → Приложения → Особые разрешения → Слушатель уведомлений → BankNotify → Включить
```

### 2. Ввести токен Telegram и Chat ID

В приложении:
1. Нажми **Настройки**
2. Введи Telegram Token и Chat ID
3. Нажми **Сохранить**

### 3. Протестировать

Нажми **Тестировать отправку** — должно прийти сообщение в Telegram

## Надёжная доставка

Push-уведомления и банковские SMS сначала сохраняются в локальную очередь Room.
Сообщение считается доставленным только после успешного HTTP-ответа и подтверждения
`ok=true` с `message_id` от Telegram. При ошибках оно остаётся в очереди; WorkManager
повторяет отправку с задержками 30, 60, 120, 240, 300 секунд, далее — по 300 секунд.
Это планируемые интервалы: Android и отсутствие сети могут отложить запуск.
Пауза `retry_after` от Telegram также соблюдается. Повторы не ограничены числом попыток:
при неверном токене, Chat ID или правах бота исправьте настройки, и очередь продолжит работу.
Сохранение и импорт настроек, а также успешный Тест запускают раннюю попытку для ожидающих сообщений,
сохраняя запрет Telegram на отправку до `retry_after`. Одновременные задания одной записи
сериализованы; они повторно проверяют подтверждение доставки перед отправкой.
Используются текущие настройки канала, включая изменения после приёма оплаты.

Очередь переживает закрытие приложения, остановку процесса и перезагрузку телефона.
Восстановление заданий выполняется при запуске и примерно каждые 15 минут.
После принудительной остановки приложения пользователем Android может не запускать
фоновые задания до повторного открытия приложения. Экономия батареи также задерживает их.

Слушатель переподключается с задержками 5, 10, 20, 40, 80, 160, 300 секунд, далее —
по 300 секунд. Есть постоянное фоновое задание восстановления; Android определяет
фактическое время его запуска. При отзыве доступа к уведомлениям попытки прекращаются.
Если доступ есть, но система не подключает сервис более двух минут, приложение предлагает
выключить и снова включить доступ в системных настройках. Запрос переподключения
не считается подтверждением: статус «Активен» появляется только после callback системы.
После восстановления перечитываются уведомления, которые ещё находятся в шторке.
Уведомления, которые Android не передал приложению и уже удалил, восстановить нельзя.

Повторный callback одного события не создаёт вторую запись. Отдельные оплаты с одинаковой
суммой сохраняются отдельно. Если Telegram принял сообщение, но ответ потерялся,
повтор может создать дубль — приоритет выбран в пользу доставки. Push и SMS одной оплаты
остаются отдельными источниками, автоматического объединения между ними нет.

### Резервные прокси

В поле прокси укажите адреса **по одному на строку**, основной первым:

```text
http://user:password@proxy.example:8080
socks5://backup.example:1080
```

При сетевой ошибке пробуем следующий адрес; при отказе всех сообщение остаётся в очереди.
Автоматического обхода списка напрямую нет. Пустой список означает прямое подключение.
Поддерживаются HTTP-прокси (включая авторизацию) и SOCKS5 без авторизации.
Сохранение и Test проверяют формат и показывают номер неверной строки. Импорт сохраняет
старый список целиком и подсвечивает неверный прокси на главном экране. Ранее сохранённые
неподдерживаемые маршруты пропускаются при фоновой доставке, чтобы резервные прокси продолжали работать.
Тестовая отправка использует тот же список и тот же код доставки.
На один обход списка отведено до 8 минут, на маршрут — до 30 секунд. Для списков длиннее
16 адресов время делится между маршрутами, чтобы успеть проверить резервные адреса.
Таймаут оставляет оплату в очереди. Явный Test отправляет отдельное диагностическое сообщение;
автоматические повторы оплат всегда соблюдают сохранённый `retry_after`.

### Перенос настроек

Сначала нажмите **Сохранить**, затем **Экспорт настроек**, выберите файл и задайте пароль
от 8 символов. Файл содержит токен, Chat ID, список прокси, выбранные приложения, переключатели
и healthcheck. Данные зашифрованы AES-256-GCM с ключом PBKDF2-HMAC-SHA256.

Для восстановления нажмите **Импорт настроек**, выберите файл и введите его пароль.
Сначала проверяются пароль, целостность и формат всего файла; только затем настройки
заменяются. Поворот экрана не прерывает применение настроек. История и очередь оплат не изменяются. Системные разрешения и исключение
из экономии батареи нужно выдавать на новом телефоне отдельно. Без пароля файл не восстановить. Автоматический системный backup не переносит
зашифрованные настройки и базу оплат на другой телефон: ключ Android Keystore
туда не переносится, а восстановление старой очереди могло бы повторить отправку оплат.

### Журнал и диагностика

Пропуски не создают отдельные строки и не вытесняют ошибки: вверху журнала показаны
счётчики причин за текущий сеанс. Сам журнал ограничен 500 записями и сбрасывается
при перезапуске процесса; ошибки ожидающих сообщений дополнительно хранятся в очереди.

Кнопка **Диагностика** показывает доступ к уведомлениям/SMS, подключение сервиса,
ограничения батареи и число ожидающих сообщений. Здесь же можно включить внешний
healthcheck, указав HTTPS URL сервиса мониторинга. При исправном сервисе выполняется
GET-запрос примерно раз в 15 минут. Если слушатель отключён, не хватает нужных разрешений,
не настроен Telegram, есть ошибки доставки или очередь старше 30 минут, пинг пропускается.
Внешний мониторинг замечает отсутствие пинга; настройте в нём интервал 15 минут и запас
не менее 30 минут. URL используется напрямую, отдельно от Telegram-прокси; адрес не пишется
в журнал. До включения функции и сохранения URL внешних пингов нет.

Поведение фоновых заданий и переподключения основано на документации
[WorkManager](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)
и [NotificationListenerService](https://developer.android.com/reference/android/service/notification/NotificationListenerService).
Подтверждение доставки и ограничения запросов описаны в [Telegram Bot API](https://core.telegram.org/bots/api).

## Troubleshooting

### Приложение не получает уведомления

1. Проверь, включен ли "Слушатель уведомлений"
2. Проверь, что банковское приложение установлено
3. Перезагрузи телефон

### Сообщения не приходят в Telegram

1. Проверь токен и Chat ID в Настройках
2. Нажми "Тестировать отправку"
3. Проверь интернет-соединение

### Проблема с сборкой

```bash
./gradlew clean build
```

### Диагностика после перезапуска

Журнал сохраняет последние 500 событий (не более 256 КиБ) в закрытом каталоге приложения,
исключённом из резервных копий Android. Он содержит запуск/подключение, номер записи очереди,
тип ошибки и доступную системную причину завершения процесса; токены, пароли прокси,
сырой текст уведомления и сообщения исключений в него не записываются. Частые пропуски
считаются отдельно за сеанс. Запись асинхронная: последние ещё не сброшенные события могут
потеряться при аварийном завершении. «Очистить» удаляет и сохранённую историю.

При недоступности Keystore приложение показывает ошибку и кнопку повторного открытия,
сохраняя файлы настроек и ключи. Недоступные до восстановления настройки могут препятствовать
приёму новых уведомлений; уже сохранённые оплаты остаются в очереди.
